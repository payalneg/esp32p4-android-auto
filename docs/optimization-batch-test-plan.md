# Ветка `perf/optimization-batch` — что изменено и как проверять

Статус на момент создания ветки: **код собирается** (waveshare / ESP32-P4,
ESP-IDF 5.5.6, `build_opt`), **на железе не проверялся**. Всё, что ниже в
разделе 4, нужно прогнать руками на каждой затронутой плате.

Цель ветки — снять самые дорогие из найденных издержек, не меняя поведение
прошивки. Каждый пункт обратим независимо (см. раздел 6).

---

### Измеренный эффект по размеру

`build_opt` (waveshare, `-O2`, блоб BT-агента остаётся в образе):

```
до:    4 711 056 B (4.49 MiB)  — -Og
после: 4 720 080 B (4.50 MiB)  — -O2
```

То есть `-O2` практически не изменил размер: прирост кода съеден удалённым
мёртвым кодом/шрифтом. Основной выигрыш — скорость, а не flash. Свободного
места в 5 МБ слоте JC4880 остаётся ~511 КБ (10 %), как и до ветки, поэтому за
размером всё ещё нужно следить (`idf.py size` в релизе).

`.bss` не вырос (~118 КБ).

> Отдельно проверялась экономия 560 КБ выключением `BT_AGENT_OTA_ENABLED`:
> образ уходил к 3.84 MiB, но терялось авто-обновление D1 Mini. **По решению
> владельца опция оставлена включённой** (см. `sdkconfig.defaults`); при
> необходимости разового маленького образа её можно выключить.

## 2. Сборка и проверка конфигурации

### 2.1 Окружение

Проект собирается ESP-IDF **5.5.6** (`build_waveshare/project_description.json`);
домашний `idf.py` без `export` может подхватить другой IDF. На Windows:

```bat
C:\esp\v5.5.6\esp-idf\export.bat
```

Если `idf.py` пишет про `idf5.5_py3.13_env` / `esp_idf_monitor` — активирован
не тот venv; используйте `C:\esp\python_env\idf5.5.6_py3.13_env` (именно его
ждали существующие build-каталоги).

### 2.2 Важно: существующие build-каталоги не подхватят defaults

`CONFIG_*` из `sdkconfig.defaults` применяются только при **создании**
`build_<board>/sdkconfig`. Если каталог уже есть, там останется старый `-Og`.
(`BT_AGENT_OTA_ENABLED` в этой ветке не менялся — он и так `y`.) Перед
проверкой:

```powershell
# пересоздать конфиг конкретной платы (сборка пойдёт заново, ~10-15 мин)
Remove-Item build_waveshare\sdkconfig
scripts/build_board.sh waveshare build
```

и убедиться, что значения применились:

```powershell
Select-String build_waveshare\sdkconfig -Pattern `
  "COMPILER_OPTIMIZATION_PERF|BT_AGENT_OTA_ENABLED"
# ожидается:
#   CONFIG_COMPILER_OPTIMIZATION_PERF=y
#   CONFIG_BT_AGENT_OTA_ENABLED=y
```

Быстрая альтернатива без полной пересборки — временно поправить
`CONFIG_COMPILER_OPTIMIZATION_PERF=y` в `build_<board>/sdkconfig` руками
(IDF перегенерирует `sdkconfig.h`).

> Если при генерации конфига сборка падает на `CONFIG_WIFI_RMT_* undeclared`
> — это не эта ветка: `esp_wifi_remote` 0.13.0 ищет `idf_v$ESP_IDF_VERSION`, а
> для 5.5.6 такого каталога в компоненте нет. Обход: скопировать
> `managed_components/espressif__esp_wifi_remote/idf_v5.5` в
> `.../idf_v5.5.6` (каталог gitignore'ится) либо выставить
> `ESP_IDF_VERSION=5.5` перед `idf.py reconfigure`.

### 2.3 Размер

```powershell
scripts/build_board.sh waveshare size
scripts/build_board.sh jc4880   size
```

Ориентиры: P4-образ ≈ **4.50 MiB** (как и до ветки). Для JC4880 слот 5 МБ —
должно остаться ≥ 490 КБ. Если образ подрастёт выше 4.9 MiB, переключаемся на
`CONFIG_COMPILER_OPTIMIZATION_SIZE=y` (`-Os`): он почти всегда быстрее `-Og`
и заметно меньше `-O2`.

## 3. Быстрый смоук (10 минут, без телефона)

1. Прошить: `scripts/build_board.sh waveshare -p COMx flash monitor`.
2. Дождаться сплэша и дашборда. В логе не должно быть `Guru Meditation`,
   `Task watchdog`, `assert failed`.
3. В логе при старте AA-стека (только при `CONFIG_AA_ENABLE`):
   `display_video: video draws into panel framebuffers (zero-copy submit)`.
   Если вместо этого `no panel framebuffers — private video fbs (copy path)` —
   включился fallback: работает, но проверка zero-copy не удалась, сообщите.
4. Пройти по экранам: дашборд (все темы), Settings, Statistics, файлы,
   навигатор (если NAV_ENABLE), экран AA (пустой).
5. Ни на одном экране не должно быть пустых прямоугольников вместо букв
   (это был бы признак вырезанного шрифта).
6. `render: N fps` на статичном дашборде должен быть **0** через несколько
   секунд после остановки таймеров/музыки (см. 4.3).

## 4. Матрица проверок

### 4.1 Android Auto: видео и фреймбуферы — главное

Это единственное изменение с реальным риском визуального дефекта.

Подготовка: телефон с AA, Mode A или B по вашей конфигурации.

1. Подключить телефон, дождаться проекции.
2. Смотреть 2-3 минуты видео/анимацию:
   - нет вертикальных полос/тиринга;
   - нет «залипшей» половины кадра;
   - нет зелёных/чёрных кадров;
   - в логе нет `panel_draw_bitmap (yuv420+ppa): ...` (это ошибка PPA).
3. Пощупать тач в AA (карта, список) — отклик не хуже, чем на старой прошивке.
4. **10 раз** переключить AA → VESC → AA трёхпальцевым жестом, в том числе
   во время движения картинки. После каждого возврата:
   - дашборд отрисован полностью (нет остатков видео);
   - следующая AA-сессия показывает видео, а не чёрный экран.
5. Оставить AA на 10 минут: не должно быть роста задержки и «догоняния»
   картинки (признак того, что PPA/display-таск встал).
6. Микрофон (если `ENABLE_AUDIO`): голосовой запрос в AA проходит.

Ожидаемый побочный эффект: **первый** кадр после входа в AA может быть
порван на один кадр (видео начинает рисовать в тот DPI-буфер, который в этот
момент сканируется). Это нормально; если тиринг виден постоянно — это баг.

Замер (нужен debug-лог, см. 5): `h264_pipe: decoded N fr (avg ... us/fr)` и
`display_video: AA show: ...` — сравнить со старой прошивкой. Ожидаем: время
кадра не хуже, `push blocked` не растёт.

### 4.2 HUD поверх AA

1. В AA цифры скорости и заряда на месте, читаемы, не мигают.
2. Значения меняются (покрутить колесо / включить BMS).
3. «N/A» при отсутствии батареи; иконка CC при cruise.
4. При перевороте экрана (Settings → Flip) HUD остаётся внизу, не зеркалится.

### 4.3 Плитка музыки (дашборд)

Было: каждые 400 мс плитка (344×136) инвалидировалась и перерисовывалась,
даже если ничего не менялось.

1. Включить музыку на телефоне, дашборд на экране VESC.
2. Трек играет, обложка на месте, кнопки prev/play/next работают.
3. Пауза → иконка play; смена трека → обложка/название/артист обновились.
4. Трек без обложки → placeholder-квадрат с иконкой; YouTube → 16:9 превью.
5. Остановить музыку → плитка скрывается, дашборд остаётся.
6. Смотреть `render: N fps` на стоящем дашборде с играющей музыкой и
   неизменными цифрами: должно быть **0-1 fps**, а не стабильные 2-3.
7. Нажать на кнопки в плитке — нет визуальных артефактов, нажатие срабатывает.

### 4.4 Навигатор (если `CONFIG_NAV_ENABLE`)

1. Открыть навигатор, дать телефону прислать позицию.
2. Карта едет, подписи улиц не дёргаются и не мерцают (4.4: кэш позиций).
3. Зум +/−, перетаскивание, кнопка «к себе» — карта и подписи корректны.
4. Маршрут: линия, стрелка поворота, оставшееся расстояние.
5. Поворот карты (AUTO/NORTH) — подписи остаются горизонтальными.
6. PNG-тайлы (телефон без vector-пакета) и vector-тайлы (NVT1 на SD) —
   оба варианта рисуются, при зуме нет «дыр» дольше пары секунд.
7. Долгий драг по карте: нет роста задержки, нет OOM.
8. Если есть SD: вынуть/вставить карту с тайлами, перезайти — тайлы грузятся
   (проверка `s_png_rgb`).

### 4.5 Статистика поездок

1. Покататься/постоять так, чтобы в лог попали записи (10 с на запись), или
   использовать уже накопленные.
2. Settings → Statistics: список поездок открывается заметно быстрее, чем на
   старой прошивке; **цифры те же** (сравнить 2-3 строки с прошлой версией:
   дистанция, время, Ah, max speed).
3. Открыть график поездки: те же значения, время открытия < 0.5 с.
4. Удалить поездку → она исчезает, после перезагрузки не возвращается.
5. После проверки — посмотреть, что новая поездка пишется (в списке
   появляется текущая).

### 4.6 Веб-файловый менеджер (`http://<ip>/files`)

1. Загрузить новый файл (в `/vescfs` и на SD) — появляется, размер верный.
2. Загрузить файл **поверх существующего** — содержимое заменилось.
3. Оборвать загрузку (закрыть вкладку/выдернуть Wi-Fi) на середине:
   - старый файл **на месте** и целый;
   - в каталоге не остаётся `<имя>.part` после повторной загрузки.
4. Загрузить пустой файл (0 байт) — ответ 400, ничего не создаётся.
5. Переименовать/удалить — работают как раньше.

### 4.7 BT-агент (Mode A) — без изменений, регрессия

`BT_AGENT_OTA_ENABLED` остаётся `y`: вшитый блоб агента (560 КБ) и авто-OTA
сохранены. Проверяем, что не сломали:

1. Спаривание телефона через BT-агент работает (Mode A).
2. Settings показывает версию BT-агента.
3. Если версия агента в Settings не совпадает с `BT_AGENT_FW_VERSION`
   (0.6.7), при старте видно, как P4 перепрошивает D1 Mini и перезагружается.
4. В логе нет ошибок `bt_agent_ota` / `esp_loader`.

### 4.8 Шрифты и экраны

Вырезаны неиспользуемые размеры Montserrat (8/10/22/26/28/30/34/36/38/40/42/
44/46) и `aabridge_font_38`. Если какой-то экран всё-таки ссылался на них —
сборка упадёт на линковке (это и есть проверка). После сборки проверить
визуально:

- Settings (все вкладки), Statistics, файлы, OTA-экран;
- все темы дашборда (Cockpit / Amber / Twin Arc / generic);
- тосты уведомлений (иконка-буква, заголовок, текст);
- музыка (название/артист, кириллица и польские буквы);
- навигатор (подписи, клавиатура, поиск);
- AA HUD (`KM/H`, `%`, `N/A`).

Нет «квадратов», обрезанных букв и уехавших базовых линий.

### 4.9 Boot, сплэш, C6

1. Холодный старт: сплэш/GIF проигрывается, панель не мигает белым.
2. Сплэш-кадры с SD (`/sdcard/splash/*.jpg`) — путь собирается новым
   `join_path`; проверить, что кадры находятся (если каталог есть).
3. Settings → версия C6: строка не пустая и не «мусор» (правка
   `parse_embedded_image`).
4. Время от включения до дашборда — не хуже, чем раньше (записать).

## 5. Замеры до/после

Собрать **две** прошивки (старую — из `main`, новую — из ветки) и записать:

| Метрика | Как снять | Ожидание |
|---|---|---|
| размер образа | `idf.py size` / `check_sizes` | примерно как до ветки (`-O2` ~= `-Og` по размеру) |
| AA fps | debug-лог: `h264_pipe: decoded N fr` | не хуже |
| время кадра AA | `display_video: AA show: ... us/fr` | не хуже |
| render fps на дашборде | `display_init: render: N fps` | простой → 0 |
| время открытия статистики | секундомер | < 0.5 с |
| свободный heap | `HEAP_PROBE` в логе при старте | без изменений |
| boot time | от reset до первого кадра | не хуже |

Чтобы включить debug-логи для AA-статистики (она на уровне `D`):

```
idf.py -B build_opt menuconfig
# Component config → Log output → Default log verbosity → Debug
```

Либо временно добавить в `main.c`:
`esp_log_level_set("h264_pipe", ESP_LOG_DEBUG);`
`esp_log_level_set("display_video", ESP_LOG_DEBUG);`
После замеров вернуть `Info`.

Логи удобно снимать `scripts/capture.sh` (Windows: `PORT=COMx`), экран —
`scripts/uart_debug.py` (см. skill `device-screen`).

## 6. Откат

Ветка — один коммит (или последовательность), откат по файлам:

```powershell
# полностью
git checkout main -- .

# только рискованное видео
git checkout main -- main/display_video.c

# только конфиг
# в build_<board>/sdkconfig (или menuconfig):
#   CONFIG_COMPILER_OPTIMIZATION_DEBUG=y
```

BT-агент в этой ветке не менялся: `CONFIG_BT_AGENT_OTA_ENABLED=y`, блоб
остаётся в образе.

## 7. Что осталось за бортом (следующая итерация)

Сознательно **не** делалось в этой ветке, чтобы не смешивать риск:

- HUD поверх видео: 5 проходов глифов на кадр (~6 мс). Нужен спрайт/слой в
  panel-space — отдельный эксперимент с A/B по `AA show`.
- `msync` только области HUD вместо всего кадра (сейчас инвалидация 768 КБ).
- `dev_settings`: `nvs_commit` (~100 мс) на LVGL-потоке при каждом тумблере.
- Рефакторинг четырёх `ble_*_client.c` в один (2088 строк дублей).
- Полный reverse-scan `trip_log` от головы (сейчас ускорен только пропуск
  стёртых секторов; двухпроходность осталась).
- `lisp_http`: мьютекс держится во время `httpd_resp_send`.
- `BT_AGENT_OTA_ENABLED=n` освобождает 560 КБ, но лишает D1 Mini
  авто-обновления — оставлено включённым по решению владельца; годится как
  разовый рычаг, если образ перестанет влезать в 5 МБ.
- `esp_wifi_remote`: обновить компонент (Kconfig не знает про patch-версии IDF).
- FreeType (13.5 МБ объектов) собирается и не линкуется — убрать из манифеста
  `esp_lvgl_adapter`.

## 8. Чеклист приёмки

- [ ] `build_<board>/sdkconfig` содержит `COMPILER_OPTIMIZATION_PERF=y`
- [ ] `BT_AGENT_OTA_ENABLED=y` (блоб агента в образе), размер P4 ≤ 5 МБ слота
- [ ] Нет `Task watchdog`, `assert`, `Guru Meditation` за 30 минут работы
- [ ] AA: 10 переключений режимов без залипшего кадра/тиринга
- [ ] AA: HUD, тач, микрофон работают
- [ ] Музыка: смена трека, обложка, кнопки; статичный экран не перерисовывается
- [ ] Навигатор: подписи/зум/драг/маршрут/тайлы
- [ ] Статистика: цифры совпадают, открывается быстрее
- [ ] Файлы: загрузка/перезапись/обрыв/0 байт
- [ ] Mode A: спаривание через BT-агент, версия в Settings
- [ ] Все экраны без «квадратов» и обрезанных глифов
- [ ] Сплэш, версия C6, boot time — как раньше
